# 开源自部署客户端与双色界面设计

日期：2026-11-20。状态：按用户选定的 A + C 方案整理，待设计稿批准后实施。

## 1. 目标

把当前仅面向内置服务器的 Windows 入网页，升级为适合第三方自部署的开源客户端入口，同时提供精致浅色与完整深色两种视觉模式。保持原生 Walk/GDI+ 技术栈，不引入浏览器运行时，不改变 Mesh、WireGuard、FRP 或服务端协议。

## 2. 用户流程

入网页仍只有一个主要任务：连接私人网络。

- 标题使用“连接到私人网络”，说明用户可以使用项目默认服务或自己的服务器。
- 第一组字段为“服务器地址”，显示当前有效地址，示例为 `https://vpn.example.com:8443`。
- 第二组字段为“入网令牌”，保留现有掩码、显示/隐藏、粘贴和 Enter 提交能力。
- 主按钮为“连接网络”，连接中禁用服务器、STUN 和令牌编辑。
- 高级连接设置提供“STUN 地址（可选）”。留空表示按服务器主机名推导为 `host:3478`；显式填写时优先使用用户值。
- 页面显示简洁的 HTTPS、凭据本地加密和自部署提示，不堆叠技术说明。

## 3. 地址与配置语义

新增统一的服务器地址规范化函数：

- 只接受绝对 `http://` 或 `https://` URL，必须有主机名或 IP。
- 拒绝 userinfo、query、fragment 和空白字符；移除末尾 `/`。
- HTTPS 为推荐部署方式；HTTP 保留给明确选择的内网/开发部署，界面给出明文提示，不静默升级或降级。
- 空服务器地址使用构建时内置地址；空 STUN 使用已保存的显式值，否则从服务器主机名推导 `3478`。
- 显式 `-server` / `-stun` 仍优先用于开发调试；未显式传 `-server` 时启动使用已保存服务器。
- 只有规范化后的服务器 URL 与保存配置一致时，才恢复该服务器的成员凭据和管理员凭据。
- 切换服务器时使用全新的客户端 API 对象，不向新服务器发送旧服务器的成员或管理员令牌。
- 只有入网/会话验证成功后才持久化新服务器、新 STUN 和新成员凭据；失败不覆盖原有可用配置。
- 旧配置缺少新字段时继续使用原内置服务器，已有成员身份和虚拟 IP 不变。

## 4. 双色视觉系统

外观设置为“跟随系统 / 浅色 / 深色”，默认跟随系统，并持久化到当前用户的客户端设置。

浅色模式延续当前品牌蓝，但统一层级：

- 背景使用轻微冷灰，表面为白色，主文字为深蓝灰。
- 主按钮使用品牌蓝，次按钮使用表面色与细边框。
- 减少无意义阴影，以留白、细分隔线、字段标签和状态色建立层级。

深色模式采用独立调色板，不做颜色反转：

- 背景为深蓝黑，卡片为略亮的蓝灰表面，边框保持可见但低对比。
- 主文字使用柔和浅灰，次文字降低亮度但保持可读性。
- 品牌蓝提高明度，在线、警告和错误状态分别保持可区分。
- 输入框、表格、导航、按钮、提示条、FRP 页面、管理页面和后续对话框使用同一套语义色。

实现上集中管理语义色，主题切换后重绘现有窗口及原生控件；系统高对比模式优先使用 Windows 系统色。主题切换不中断 Mesh 或 FRP 会话，不重建虚拟网卡。

## 5. 主界面同步优化

- 保留现有左侧导航和圆形电源交互，不重新组织用户已熟悉的页面。
- 统一页面标题、卡片圆角、输入框高度、按钮尺寸和间距。
- 入网页从单令牌卡片升级为清晰的双字段连接卡片，高级 STUN 默认收起。
- 主界面显示当前服务器来源，便于用户确认自己连接的是默认服务还是自建实例。
- 设置页增加外观选择；保留现有 MTU、游戏低延迟、托盘和启动设置。
- 所有新增控件提供中文可访问名称、键盘焦点和 Enter/Escape 行为。

## 6. 测试与验收

- 地址规范化：HTTPS、HTTP、IPv4、IPv6、域名、端口、末尾斜杠，以及 userinfo/query/fragment/空白/无效协议。
- STUN 推导：域名、IPv4、带方括号 IPv6、自定义端口和显式覆盖。
- 启动恢复：保存服务器、显式 flag 覆盖、服务器不匹配时凭据隔离、旧配置兼容。
- 入网事务：成功才保存新配置，失败不覆盖旧配置，连接中不能重复提交。
- 设置序列化：外观、服务器、STUN 与现有游戏设置共同往返。
- UI smoke：浅色和深色入网页、主页面、设置页及对话框初始化；原生控件可访问名称不丢失。
- 使用 `-ui-preview` 分别生成浅色/深色截图，检查文字对比、裁切、焦点和缩放。
- 运行 `go test ./...`、`go vet ./...`、Windows 构建和 Linux 服务端交叉构建。

## 7. 非目标

- 不修改服务端入网协议、令牌内容或默认服务器部署。
- 不引入在线账号、服务器目录、自动发现不可信服务器或遥测上传。
- 不迁移到 Electron/WebView，不增加第三方 UI 依赖。
- 不在本轮重做 FRP 业务逻辑、成员管理逻辑或网络路径算法。
- 不允许因为切换服务器而把旧服务器凭据发送到新地址。
